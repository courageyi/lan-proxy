# LAN 认证代理（lan-proxy）设计文档

- 日期：2026-08-19
- 状态：已获用户批准（设计对话确认）
- 范围：在 DSH Web GUI（`127.0.0.1:3080`）前增加一层带登录认证的局域网反向代理

## 背景与目标

DSH Web GUI 默认只监听 `127.0.0.1:3080`，且官方明确说明 Web 载体**没有内置认证层**、`--host 0.0.0.0` 被有意禁用。用户需要让局域网内其他设备能够使用该 GUI，同时要求：

1. 局域网访问必须经过**登录页面**认证后才能进入；
2. 建立 **5 个用户账户**（`user1`–`user5`），各自随机强密码，凭据写入文件供分发；
3. **本机**直接访问 `127.0.0.1:3080` 不受影响（不要求登录）；
4. 传输使用**自签名 HTTPS**。

## 架构

```
局域网设备 ──HTTPS──> [lan-proxy :3081] ──认证通过──> HTTP ──> dsh web :127.0.0.1:3080
                         │
                         ├─ 未登录 → 登录页
                         ├─ 认证 → 会话 Cookie（HMAC 签名）
                         └─ 转发（普通 HTTP + WebSocket 升级）
```

- 代理监听 `0.0.0.0:3081`（HTTPS，自签名证书）；
- 后端 dsh 维持现状 `127.0.0.1:3080`，**不重启、不修改**；
- 本机回环访问 `127.0.0.1:3080` 完全绕过代理。

## 组件

| 文件 | 职责 |
|------|------|
| `server.js` | 主程序：HTTPS 监听、登录/会话、反向代理、WebSocket 隧道、限速（纯 Node，零第三方依赖） |
| `login.html` | 登录页（静态，内嵌于 `server.js` 或以独立文件提供） |
| `config.json` | 端口、后端目标、会话密钥、会话有效期、账号列表（scrypt 加盐哈希） |
| `credentials.txt` | 初始生成的 5 组账号密码（分发用，用后可删除） |
| `cert.pem` / `key.pem` | 自签名证书与私钥（HTTPS） |

## 数据流

1. 设备访问 `https://192.168.110.168:3081` → 无有效会话 Cookie → 302 到 `/login`，返回登录页；
2. `POST /login`（表单 `username`/`password`）→ scrypt 校验 → 成功则签发 Cookie 并 302 到 `/`；失败记录限速计数；
3. 带有效 Cookie 的任意请求 → 代理转发到 `127.0.0.1:3080`：
   - 改写请求头：`Host` → `127.0.0.1:3080`；若原请求带 `Origin` 则改写为 `http://127.0.0.1:3080`（使后端浏览器信任围栏通过：Host 为回环 + Origin 与 Host 一致）；
   - 响应原样回传；
4. WebSocket 升级（`/api` 下的 `events.mux` / `events.host`）→ 校验 Cookie → 用 `http.request` 转发升级请求（保留 `sec-websocket-*`，改写 `Host`/`Origin`）→ 收到 101 后双向管道（含 `head` 缓冲）；
5. 明文 HTTP 访问 3081 端口 → 301 跳转到 HTTPS 同地址（TCP 首字节嗅探区分 TLS/HTTP）。

## 安全设计

- **密码存储**：scrypt 加盐哈希（每用户独立随机盐），`config.json` 不存明文；
- **会话**：HMAC-SHA256 签名 Token（`base64url(payload).sig`），`HttpOnly` + `SameSite=Strict` + `Secure` + `Path=/`，有效期 12 小时；
- **限速**：按来源 IP 记录失败次数，连续失败 5 次锁定 15 分钟；成功登录清零；
- **证书**：自签名（生成优先 openssl；不可用则 PowerShell `New-SelfSignedCertificate` + PEM 导出；仍不可用则内置最小 X.509 生成器兜底），有效期 1 年；
- **防火墙**：新增入站规则放行 TCP 3081（需管理员权限，失败则给出用户手动执行的命令）；
- 已知边界：密码与流量经 TLS 加密但证书自签名，首次访问浏览器有不受信任提示；认证是访问门槛而非纵深防御，仅建议在可信局域网启用。

## 错误处理

- 后端不可达（ECONNREFUSED）→ 502 并给出友好提示；
- 无效/过期 Cookie → 302 到 `/login`；
- 登录失败 → 401 回登录页并显示错误；
- 请求体异常、头解析失败 → 400/502 落日志；
- 所有异常记入 `stdout` 日志（时间戳 + 方法 + 路径 + 状态）。

## 命令接口

- `node server.js setup` — 生成 `config.json`（会话密钥、5 个账号随机密码）、`credentials.txt`，打印凭据；缺证书时一并生成；
- `node server.js`（默认 run）— 启动代理（要求 config 与证书已就绪，否则提示先 setup）；
- `node server.js adduser <name> [password]` — 追加账号（无密码则随机生成并追加到凭据文件）。

## 测试计划

- 本地模拟验证：
  1. 无 Cookie 访问 `/` → 302 `/login`；`/login` 返回 200 登录页；
  2. 错误密码 → 401；连续 5 次 → 锁定 15 分钟（403 + 拒绝提示）；
  3. 正确密码 → 302 + `Set-Cookie`；带 Cookie 访问 `/` → 200 且内容来自 dsh（代理成功）；
  4. 带 Cookie 访问 `/api/*` → 非 403（围栏通过）；
  5. WebSocket 升级带 Cookie → 101 握手成功（隧道打通）；
  6. 明文 HTTP 访问 → 301 到 HTTPS；
  7. 无 Cookie 的 WebSocket 升级 → 拒绝；
  8. 后端 3080 未运行时 → 502。
- 局域网验证：在另一台设备打开 `https://192.168.110.168:3081` 登录并进入 GUI（由用户执行）。

## 非目标（YAGNI）

- 不改动 dsh 源码、不重启 dsh；
- 不做多因素认证、账号管理 Web 界面、TLS 证书自动续期；
- 不做每用户权限分级（5 个账号权限相同）。

## 后续维护提示

- 修改密码/加账号：`node server.js adduser` 或直接编辑 `config.json`（哈希需用 scrypt 重新生成）；
- 停止暴露：结束代理进程 + 删除防火墙规则即可恢复仅本机访问。
